## Entry points and request flow

| Layer | Entry/source | Current responsibility |
| --- | --- | --- |
| Browser document | [client/index.html](../../client/index.html), [main.jsx](../../client/src/main.jsx) | Mount React in StrictMode and load shared CSS. |
| Routing/session | [App.jsx](../../client/src/App.jsx), [AuthContext](../../client/src/context/AuthContext.jsx), [ProtectedRoute](../../client/src/components/ProtectedRoute.jsx) | BrowserRouter, login/session restoration through auth/me, authentication wrapper and owner/manager guards on sensitive screens. |
| Navigation/layout | [DashboardLayout](../../client/src/layouts/DashboardLayout.jsx) | Header, toggleable sidebar, stored group expansion and role-dependent links, including the active Restaurant Operations group. |
| HTTP client | [utils/api.js](../../client/src/utils/api.js), [ApiErrorNotice](../../client/src/components/ApiErrorNotice.jsx) | Axios base URL and Bearer token injection; 401 cleanup/redirect excludes failed login, while network/5xx failures trigger a dismissible request-error notice. |
| API process | [server/server.js](../../server/server.js) | Start HTTP server and initialize Socket.IO; PORT defaults to 5000. |
| Express application | [server/src/app.js](../../server/src/app.js) | Middleware, /health, API namespace mounts and global error handler; exported separately for tests. |
| Authorization | [middleware/auth.js](../../server/src/middleware/auth.js), [permissions](../../server/src/config/permissions.js) | Require Bearer JWT and reload the active user's role/permissions from PostgreSQL on every request; checkRole and requirePermission retain owner permission bypass. |
| Persistence | [config/db.js](../../server/src/config/db.js) | PostgreSQL pool, DATABASE_URL, query wrapper and SQL/parameter logging. The application pool preserves PostgreSQL DATE text as YYYY-MM-DD, avoiding local-midnight/UTC day shifts; TIMESTAMP parsing remains unchanged. |
| Kitchen display/events | [Workflows.jsx](../../client/src/pages/operations/Workflows.jsx), [socket.js](../../server/src/socket.js), [KDS controller](../../server/src/modules/operations/kds.controller.js) | The browser display polls active tickets every five seconds and supports refresh/status actions. The separate socket path verifies an active-account JWT and emits controller new_ticket/ticket_updated events. |
| Shared integrity helpers | [domain.js](../../server/src/utils/domain.js), [writeGuard](../../server/src/modules/finance/writeGuard.js) | Domain errors/status mapping and finite-value checks; transaction-scoped day advisory lock plus period/account closure checks for participating writers. |

Most screens hold their own React state and call Axios directly. [hooks](../../client/src/hooks/) supply reusable employee/vendor/payroll/finance/pagination helpers; their presence does not mean a page uses them. For example, [Payroll.jsx](../../client/src/pages/Payroll.jsx) calls the current POST approve/payout routes directly, while [usePayroll](../../client/src/hooks/usePayroll.js) still declares different approval/payment URLs. Trace the page's imports and calls before modifying a helper.

Typical source flow: screen → Axios → namespace mount → module routes → controller → service or controller SQL → pg pool. Services are generally exported singleton objects. Layering is mixed: [inventory controller](../../server/src/modules/inventory/controller.js) delegates to [InventoryService](../../server/src/modules/inventory/service.js), while [payroll controller](../../server/src/modules/payroll/controller.js), [reports controller](../../server/src/modules/reports/controller.js) and [PO controller](../../server/src/modules/inventory/po.controller.js) execute substantial SQL directly.

JournalService's comment that all financial transactions must flow through it is an intended design rule, not a repository-wide guarantee. [JournalService](../../server/src/modules/finance/JournalService.js) and [JournalEntry](../../server/src/modules/finance/entities/JournalEntry.js) validate/post their own inputs; callers must pass the same transaction client when atomicity is required. PO receipt and [tracker writes](../../server/src/modules/finance/TransactionService.js) now use that service, while [the importer](../../migration_tool.py) still has direct journal SQL. The compatibility finance payment now delegates to VendorPaymentService. Each path needs its own persisted-state verification. Read [accounting and HR](accounting-and-hr.md) before reconciling or changing these models.

PDF exports embed [Noto Sans](../../client/src/assets/fonts/NotoSans-Regular.ttf) and [Noto Sans Devanagari](../../client/src/assets/fonts/NotoSansDevanagari-Regular.ttf), distributed with their [SIL Open Font License](../../client/src/assets/fonts/LICENSE). Fonts load lazily through Vite asset URLs, and a failed load clears the cached promise for retry. reportPdf selects the Devanagari font for matching cells, unions object keys into columns, serializes nested values and switches to landscape above six columns. The focused audit parsed all four report-page downloads and a multipage inventory report containing Hindi and long data; it does not establish all scripts, mixed-script layouts or print presentation.

## Authorization and configuration boundaries

[App.jsx](../../client/src/App.jsx) supplies owner/manager requiredRoles to employee/menu/payroll, procurement/inventory/vendor-payment, finance, bulk-attendance/advance-approval, AI/report/config, combined-approval and recipe/PO/wastage/adjustment/employee-balance screens. POS, orders, kitchen, dashboard, advances, leaves and development-status have authentication-only page access. [DashboardLayout](../../client/src/layouts/DashboardLayout.jsx) exposes POS/orders/kitchen to authenticated users and the other operations links to owner/manager. Backend guards remain mixed: finance/inventory/POS use permissions; payroll/employees use role checks; [reports](../../server/src/modules/reports/routes.js) and [config](../../server/src/modules/config/routes.js) require active authentication plus owner/manager; [vendors](../../server/src/modules/vendors/routes.js) require FINANCE_READ, with FINANCE_WRITE additionally required for payment POST. [AUTH tests](../../tests/audit/auth.spec.cjs) and the [completion staff-denial case](../../tests/audit/completion.spec.cjs) check selected direct page/API access; menu visibility is separate from those checks.

[PERMISSIONS](../../server/src/config/permissions.js) now defines HR_WRITE and grants it to managers for [leave](../../server/src/modules/leaves/routes.js) and [standalone advance](../../server/src/modules/advance-requests/routes.js) approval. SYSTEM_ADMIN is defined, while the [finance reopen route](../../server/src/modules/finance/routes.js) still references undefined ADMIN and relies on the owner's bypass. [middleware/rbac.js](../../server/src/middleware/rbac.js) declares another vocabulary, while these routers import middleware/auth.js. Verify the guard actually imported by a changed route; source-level guard repair does not certify all ownership/role combinations.

[ConfigService](../../server/src/modules/config/service.js) reads active config_options by default; [ConfigManager](../../client/src/pages/config/ConfigManager.jsx) requests includeInactive=true so options remain reachable for reactivation. Mutations are category-scoped and updates preserve omitted fields. [PaymentModeService](../../server/src/modules/finance/PaymentModeService.js) separately resolves active payment_modes by canonical name or display_name, with a Bank Transfer alias. [PaymentModeSelect](../../client/src/components/finance/PaymentModeSelect.jsx) submits mode.name while displaying display_name. getPaymentMode/validatePayment still match canonical name only; config_options do not automatically synchronize payment_modes. See CFG-001–003 in [reports-config-ai.spec.cjs](../../tests/audit/reports-config-ai.spec.cjs).

[app.js](../../server/src/app.js) now withholds CORS authorization for unlisted browser origins; requests without Origin and the configured/local allowlist remain accepted. CORS does not replace API authorization. [socket.js](../../server/src/socket.js) configures Socket.IO CORS for CLIENT_URL (default localhost:3002) and verifies a handshake JWT against an active user before connection. Any authenticated active user can still join the kitchen room; there is no kitchen-specific role guard in that handler. [AUTH-011](../../tests/audit/auth.spec.cjs) checks untrusted HTTP Origin and anonymous socket connection, without certifying every allowed-origin/transport/role or reconnect/revocation scenario.

## Schema, deployment and tests

[Canonical baseline and lookup defaults](corrections-and-valuation.md) are the active schema authority. [Migration engine](../../server/scripts/migration-engine.js) verifies checksums and serializes fresh initialization; the CLI requires explicit DATABASE_URL and offers a read-only check. Exact recorded legacy 53/54-file schemas support reviewed adoption; older/custom/business-data plans remain separate. [Bootstrap evidence](../audit/phase2/bootstrap.json) records the same canonical files used by audits.

[Compose](../../docker-compose.yml) initializes PostgreSQL without competing SQL-directory mounts. [Server image](../../server/Dockerfile) uses repository-root context, packages canonical SQL, and runs migration before API startup. [Client image](../../client/Dockerfile) still serves Vite development mode; production static hosting remains separate. Full guarded audit uses PostgreSQL 14; [container evidence](../audit/phase2/container-verification.json) verifies fresh initialization and real API/Chromium refund smoke on PostgreSQL 15. The reusable npm run test:docker command creates a unique disposable project and removes only its synthetic containers/volumes.

For changes, combine the appropriate [mocked server tests](../../server/tests/) or [client tests](../../client/src/tests/) with reached browser/API/database assertions in [tests/audit](../../tests/audit/). The root [JavaScript](../../playwright.config.js)/[TypeScript](../../playwright.config.ts) configurations and [client Playwright config](../../client/playwright.config.js) all forward to the same [absolute-path audit configuration](../../playwright.audit.config.cjs). Historical [tests/e2e](../../tests/e2e/) files remain source references outside the active default suite. The harness owns isolation, fixed business time, evidence attachment and cleanup; see [fixtures](../../tests/audit/fixtures.cjs), [clock](../../tests/audit/clock.cjs) and [global teardown](../../tests/audit/global-teardown.cjs).

The [POS workflow reference](pos.md) describes table configuration, query-string navigation, legacy saved drafts and the new browser/API test ownership.
