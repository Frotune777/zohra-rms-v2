## Evidence vocabulary

- **Source verified** means the linked source declares or implements the described path. It does not establish that the path succeeds.
- **Runtime verified** means a named test has executed and its reached assertions are recorded in [phase 2 results](../audit/phase2/results.json). A test title or mapped checklist ID alone is not proof.
- **Reproduced defect** means executed evidence documents a failed assertion or incorrect persisted state. Use the report and attached evidence to distinguish a status mismatch from data corruption.
- **Unresolved policy** means a business expectation is not settled. Read [decisions](decisions.md); avoid treating comments, historical manuals or provisional assertions as approval of a rule.

This reference maps source and verification locations. It deliberately links mutable audit findings instead of maintaining a second list of pass/fail counts. Phase 1 remains a historical checkpoint. Phase 2 report/result/coverage artifacts are regenerated by audit work; check that results and coverage belong to the same completed run before citing them.

## Dependencies and routine commands

There are three independent npm packages and lockfiles: [root](../../package.json), [client](../../client/package.json) and [server](../../server/package.json). [.nvmrc](../../.nvmrc) pins Node 26.13.0; all three packages declare Node >=24. Python dependencies are pinned in [pyproject.toml](../../pyproject.toml) and [uv.lock](../../uv.lock). Exact resolved versions and upgrade evidence are in the audit, rather than this guide.

From the repository root, with the pinned Node runtime selected:

~~~sh
npm ci
npm --prefix client ci
npm --prefix server ci
uv sync --locked
npm run build
npm run test:client
npm run test:server -- --runInBand --coverage
~~~

[Root scripts](../../package.json) forward build/client/server checks to their packages. [Vitest configuration](../../client/vite.config.js) discovers only client source tests; [Jest configuration](../../server/jest.config.js) discovers server/tests and requires 70% global coverage. Jest includes domain, mocked and real PostgreSQL/Express integration tests; [the test guide](jest-testing.md) maps scenario ownership, isolation and assertion quality. Current exact assertion, build and coverage results are in [phase 2 validation](../audit/phase2/validation.json). `npm run test:coverage` combines same-run V8 unit and real API/Playwright coverage under the unchanged 70% global thresholds; the default standalone Jest command retains its separate coverage result. Phase 1 verification is historical.

For an already initialized, explicitly selected development database, start separate terminals with:

~~~sh
npm --prefix server run dev
npm --prefix client run dev
~~~

[Database configuration](../../server/src/config/db.js) requires DATABASE_URL and loads the root .env; [JWT middleware](../../server/src/middleware/auth.js) requires JWT_SECRET. [Vite](../../client/vite.config.js) defaults to port 3002; [server.js](../../server/server.js) defaults to 5000; [Axios](../../client/src/utils/api.js) defaults to http://localhost:5000/api and accepts VITE_API_URL. Set environment values for the selected local setup; the template's PostgreSQL hostname is the Compose service name. Starting these processes does not initialize or repair a schema.

## Browser, API and database verification

Both root test:audit and test:e2e use the [guarded audit configuration](../../playwright.audit.config.cjs), with [playwright.config.js](../../playwright.config.js) forwarding to it. List cases without starting the harness or replacing its reports:

~~~sh
npm run test:audit -- --list --reporter=list
~~~

For an actual run, follow the complete prerequisites and isolation procedure in the [phase 2 report](../audit/phase2/README.md). The harness expects a disposable cluster at /private/tmp/zohra-audit-pg, user zohra_audit, host 127.0.0.1 and port 55439; [the guard](../../tests/audit/database.cjs) rejects other targets. [Global setup](../../tests/audit/global-setup.cjs) verifies the actual cluster directory and bootstraps a template; [fixtures](../../tests/audit/fixtures.cjs) clone and clean one database/API process per test. Chromium uses client/API ports 33129/33130, one worker and no retries. The canonical checksum engine serves audit, CLI and Docker initialization; synthetic seed/reset and case isolation remain audit-specific.

~~~sh
npx playwright install chromium
npm run test:audit
python3 scripts/summarize-playwright-audit.py
npx playwright show-report playwright-report/audit
~~~

For a focused fix, use a file and/or checklist filter, then inspect the generated result and persisted evidence:

~~~sh
npm run test:audit -- tests/audit/pos-inventory.spec.cjs --grep 'POS-004'
~~~

Filtered runs overwrite the audit result artifacts with selected-run evidence. They must not be represented as a complete audit; rerun the full suite before publishing a full-run coverage summary. The [reporter](../../tests/audit/reporter.cjs) emits results, the [summary script](../../scripts/summarize-playwright-audit.py) emits coverage, and failure traces/screenshots/server logs are stored under test-results/audit. Named test locations are in [feature routing](feature-routing.md).

## Maintenance boundaries

Update only the relevant reference section when an entry point, route, data model or verification command changes, and include its source/test link. Read the failing test and exact assertions before changing behavior. After a fix, verify the UI/API contract and committed database effects in the applicable audit case; passing navigation or mocked unit tests alone does not close a feature's remaining scope.

[database](../../database/) contains historical SQL with competing definitions, while [server migrations](../../server/migrations/) and [nested finance migrations](../../server/src/modules/finance/migrations/) supply other contracts. The [migration runner](../../server/scripts/migrate.js) now requires explicit DATABASE_URL and uses the immutable canonical baseline/defaults; see [migration contracts](corrections-and-valuation.md). Fresh canonical schemas contain lookup defaults and no sample business rows. The [demo seed](../../scripts/demo-seed.cjs) is invoked only for a fresh guarded sample database; it is not a business-data migration. The importer [migration_tool.py](../../migration_tool.py) mutates business data and employee status; use its isolated [round-trip tests](../../tests/audit/data-roundtrip.spec.cjs) when investigating it.

Historical manuals, saved reports and [DevelopmentStatus](../../client/src/pages/DevelopmentStatus.jsx) describe prior intent or static claims. [Docker Compose](../../docker-compose.yml) declares PostgreSQL 15 and different host ports. [Separate container evidence](../audit/phase2/container-verification.json) establishes fresh initialization and API/Chromium refund smoke; production deployment and upgrades of custom existing schemas remain outside that scope. Keep the historical [GAP_ANALYSIS](../../documentation/GAP_ANALYSIS.md) and audit checkpoints intact; place current findings in the current audit/reference documents.
