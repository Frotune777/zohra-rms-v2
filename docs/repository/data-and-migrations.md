## Selected schema and active writers

This map describes the selected audit schema through 046, not a business database's actual schema. Money generally uses two-decimal NUMERIC/DECIMAL; current inventory quantities use four decimals. Timestamps are predominantly TIMESTAMP without time zone. Source references and many status comments remain application contracts rather than relational constraints.

## Canonical initialization and audit bootstrap

[Canonical baseline and lookup defaults](corrections-and-valuation.md) now serve the CLI, Docker and disposable audit. The [migration engine](../../server/scripts/migration-engine.js) verifies file checksums, serializes initialization and refuses untracked/custom existing schemas. The CLI requires explicit DATABASE_URL; --check is read-only. Reviewed --adopt-verified supports the exact prior 53/54-file audit schemas, applying 047 for 53 and checking a strict legacy catalog fingerprint before recording canonical history. Production/business-data migration remains outside authorization.

Fresh initialization installs two immutable canonical files without sample employees, users, suppliers, menu or stock. The audit seeds its own synthetic data; the demo runner seeds only when creating a fresh sample database. Legacy SQL alternatives and their recorded ordering remain historical under [the previous migration context](../audit/phase2/before-remaining/migration-context.md), not the active bootstrap authority.

Migration 047 adds cent-accurate stock value, receipt/correction history, exact manual advance allocations/reversals and full-order refund history. Its reviewed definitions are included in the canonical baseline. Existing stock_value is nullable until the first recorded value writer, retaining the requirement to reconcile historical balances. No opening journal is fabricated by schema initialization. Fresh PostgreSQL 15 Docker smoke evidence is separate from the full guarded PostgreSQL 14 audit.

[Fixtures](../../tests/audit/fixtures.cjs) clone one isolated case database per test and retain canonical schema history/lookup defaults during synthetic reset. The guard still requires user zohra_audit, 127.0.0.1:55439, known cluster directory and zohra_pw_* names. The initial audit has a fixed business clock; the manual demo uses ordinary application time. Preserve completed artifacts before focused audits because the reporter overwrites them.

## Import contracts after the current repair

[DataMigrator](../../migration_tool.py) remains a direct SQLAlchemy writer and catches many step errors. Its default pipeline prepares→employees→rates→bills→attendance→ledger→status sync; no transaction covers the complete import. It is tested with synthetic files, never supplied business workbook/CSV contents.

| Method | Current behavior |
| --- | --- |
| prepare_db | Inserts default supplier, tries full_name/position employee uniqueness and catches constraint errors. Imported source/operation tables come from043, not this preparation method. |
| migrate_employees | EMP List Name/Role/Department/Salary/Key; deduplicates Name/Role/Department, constructs position, generates row-index code, upserts full_name/position and updates salary/code. In-memory source key→employee map drives attendance. |
| migrate_chicken_rates | Paper Rate Date/Tandoor/Boiler/Egg; missing rate zero; date ON CONFLICT DO NOTHING preserves existing value/status on rerun. |
| migrate_vendor_bills | Chicken Daily weight date/cut positive quantities; Pending bill with zero rates/variance. Now source key bill:file-SHA256:row-index:cut is advisory-locked and inserted with bill in one transaction, so byte-identical repeat files skip. No stock/journal/vendor liability posting or corrected-file business-key matching. |
| migrate_attendance | Month-year sheets, day columns row1, data from row4, matched importer identity. Present/P, absent/off/A, half mapping; other nonblank Absent. Unknown employees/invalid dates skip; existing employee dates remain unchanged. Clears active set and completion flag at start; completes only after successful parse with matched employees. |
| migrate_ledger | Date/Amount/Category/Item/Description/Remarks headers (Item/Description is one header); mixed day-first dates and finite positive amounts. Byte-level keys prevent identical-file duplication; changing/reordering/reformatting a file creates new keys and can duplicate the same business events. Bill target_id is not populated by the current import, while ledger target_id stores journal UUID. Imported journals bypass central finite/entity/closure guard logic even though current CSV amounts are validated; SQL journal period triggers still apply. Handling corrected historical imports and failed partial stages requires a broader migration design. Separate [Node tracker](../../server/scripts/import_daily_tracking.js)/[chicken](../../server/import_chicken_data.js) importers use different direct writes and are not covered by DataMigrator evidence.

Python [dependencies](../../pyproject.toml) include Psycopg2 and3; SQLAlchemy2.1.8's URL driver now has Psycopg3/binary support. Baseline DATA-001 verified synthetic XLS/XLSX employee/rate/attendance repeatability and reproduced duplicate bill/CSV/missing-attendance failures. [Accessibility-import-export](../audit/phase2/fixes/accessibility-import-export/results.json) now passes those synthetic repeat/invalid-row/missing-attendance assertions and reaches the purchase/settlement/closure and attendance/advance/payout/revert round trips. E2E-003 ends after reverted cash/advance balance checks despite “repay” in its title; deduction-bearing repayout is separately covered in integrity regressions. Neither artifact verifies corrected-file imports or actual business data.
