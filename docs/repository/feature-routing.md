## Route variants and contract traps

The [Jest scenario guide](jest-testing.md) now maps domain and real PostgreSQL/Express tests alongside the browser cases below, including invalid inputs, source identity, late rollback, retries and selected controlled races. Its [completed evidence](../audit/phase2/jest-expansion/verification.json) retains exact counts and unchanged coverage thresholds.

These are source facts verified by comparing the linked callers and routers. A similarly named endpoint is not necessarily the same workflow.

| Concern | Where to trace |
| --- | --- |
| Chicken namespace | [app.js](../../server/src/app.js) mounts the same [inventory router](../../server/src/modules/inventory/routes.js) at /api/chicken and /api/inventory. A router change affects both aliases. |
| Menu editing | [MenuManagement](../../client/src/pages/MenuManagement.jsx) now opens an edit form and PUTs menu/:id. [POS routes](../../server/src/modules/pos/routes.js) register it; [PosService.updateMenuItem](../../server/src/modules/pos/service.js) validates name/category/finite positive price and updates the row. MENU-001 checks the edit button exists, but does not submit an edit and assert persisted fields. |
| POS draft/checkout/retry/print | [POS](../../client/src/pages/POS.jsx) stores cart/type/mode/details and the last request/key in actor-scoped sessionStorage. An unchanged failed request reuses the key across reload; changed content gets a UUID. [PosService](../../server/src/modules/pos/service.js) compares JSONB requests under a user-scoped operation_keys lock; the same key with changed content returns 409. SAVE, SAVE & PRINT, SAVE & KOT and PRINT & KOT all commit checkout; print variants render the committed response through flushSync before window.print. Receipt lines/discount/tax/paid/due use that response. Ticket persistence and browser print invocation do not establish socket delivery or printed layout. |
| Financial source corrections | [Corrections and valuation](corrections-and-valuation.md) describes full-order refunds, exact manual FIFO/installment reversal and stock/wastage corrections. Owner/manager browser actions retain source/actor/reason and retry state; cooked stock remains deducted. |
| Vendor access and ledger filters | Vendor routes require FINANCE_READ; payment POST also requires FINANCE_WRITE. Staff cannot read or pay vendors. End-date-only ledger requests allocate SQL parameters correctly; the correction regression covers the filter, role rejection, required payer validation, optional notes and persisted payment journals. |
| POS discounts/Due/Part/settlement | [PosService](../../server/src/modules/pos/service.js) validates stored-price line quantities/type/discount, proportionally allocates the fixed discount before tax in cents, and persists customer/table/notes/totals. Due has zero collected payment; Part requires a positive amount below total and partialPaymentMode. Outstanding orders debit receivable 1120; customerPhone is optional for all payment modes. [OrderPayments](../../client/src/pages/operations/OrderPayments.jsx) sends a required Idempotency-Key for settlement, replacing it when amount/mode changes. Order row locks prevent overcollection; payment/journal/paid_amount/Part-or-Paid updates commit together. Checkout's retry key remains optional at the API boundary, though the UI supplies it. |
| Bill creation/status | [InventoryService](../../server/src/modules/inventory/service.js) commits only the Pending source bill; approval receives matching stock and posts liability/journal atomically. [Inventory routes](../../server/src/modules/inventory/routes.js) use PATCH bills/:id/status for locked approval/rejection with liability/journal posting; repeated same status returns the row and Approved cannot return to Pending. [ApprovalsDashboard](../../client/src/pages/ApprovalsDashboard.jsx) also calls this route, so its actions need the same transition contract. |
| Attendance variants | [BulkAttendance](../../client/src/pages/BulkAttendance.jsx) uses /api/attendance and the [standalone service](../../server/src/modules/attendance/service.js). /api/employees/attendance uses [Employee AttendanceService](../../server/src/modules/employees/AttendanceService.js). Both now call [validateBulk](../../server/src/modules/attendance/validateBulk.js) for supported statuses, active employee, locked attendance and approved-leave protection, with different transaction owners. |
| Payroll variants | [Payroll page](../../client/src/pages/Payroll.jsx) uses the [standalone router/controller](../../server/src/modules/payroll/routes.js). Employee [PayrollService](../../server/src/modules/employees/PayrollService.js) and standalone run now share [buildDrafts](../../server/src/modules/payroll/drafts.js); employee monthly reads the same salary_history values through [EmployeeService](../../server/src/modules/employees/EmployeeService.js), with a narrower projection that omits payroll row ID/status. Payout/reversal is owned by [lifecycle](../../server/src/modules/payroll/lifecycle.js), with source locks, FIFO allocations and source-scoped reversals. Negative payouts create an employee shortfall rather than negative cash disbursement; [shortfalls](../../server/src/modules/payroll/shortfalls.js) provides settlement and owner reversal. [usePayroll](../../client/src/hooks/usePayroll.js) still declares unregistered PUT payroll/:id/approve and POST payroll/:id/payment URLs. |
| Advance request variants | [Advances](../../client/src/pages/Advances.jsx), [AdvanceApprovals](../../client/src/pages/AdvanceApprovals.jsx) and [ApprovalsDashboard](../../client/src/pages/ApprovalsDashboard.jsx) call /employees/payroll/* through [AdvanceService](../../server/src/modules/employees/AdvanceService.js). Separate /advance-requests keeps its [controller](../../server/src/modules/advance-requests/controller.js), but approval now disburses through that shared service. [advanceSchedule](../../server/src/modules/employees/advanceSchedule.js) creates cent-exact installments and synchronizes manual/payroll recovery and payroll reversal through journal-linked allocations. This later source change is outside the two completed focused runs; inspect its new ADV/PAY assertion in [completion](../../tests/audit/completion.spec.cjs) and later results. See [accounting and HR](accounting-and-hr.md). |
| Advance employee filter | [Advances](../../client/src/pages/Advances.jsx) now uses a relative employees/payroll/advances/:id URL, honoring VITE_API_URL. [Employee controller](../../server/src/modules/employees/controller.js) passes the ID to [AdvanceService.getAllAdvances](../../server/src/modules/employees/AdvanceService.js), which filters the ledger.
